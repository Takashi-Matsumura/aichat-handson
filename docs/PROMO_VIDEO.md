# 展示会ブース用の紹介動画（30 秒 CM）

IT 展示会のブースで流す、このアプリの紹介動画。パンフレット（TED パンフレット 2026）の
「STEP 1 AIリテラシー研修」で使うアプリとして、特徴のある機能を 1 本 30 秒で 1 つずつ見せる。
作り方は BoX4 の CM（cheetah-frame リポジトリの `apps/web/promo/`・`docs/PROMO_VIDEO.md`）にそろえている。

## 1. 仕様

| 項目 | 内容 |
|------|------|
| 長さ | 1 本 30 秒 × 4 本。4 本をつないだループ用の 1 本（2 分）も作る |
| 画面 | 16:9・1920x1080・30fps・mp4（H.264） |
| 音 | **無音**（字幕のみ。ブースは騒がしいので、音が無くても伝わる作りにする）。無音の音声トラックを 1 本入れてある |
| 見る人 | 社内で生成 AI の研修を考えている人。通りすがりに数秒見て、足を止めるかを決める |

## 2. 構成

1 本 30 秒の型（全本共通）:

| 秒 | 内容 |
|----|------|
| 0–4 | 問いかけ（研修の現場の「あるある」を 1 文） |
| 4–7 | タイトル（「CM 0N　AIリテラシー研修　AIチャット ハンズオン」と主題） |
| 7–24 | アプリの画面（字幕 2〜3 枚） |
| 24–30 | 締め（全本共通）: STEP 1 AIリテラシー研修 ／ まずは、AIを正しく使うところから ／ 生成AIの基礎・情報管理の注意点・業務での活用例 ／ OCC のロゴ |

| CM | 問いかけ | タイトル | 画面 | 字幕 |
|----|----------|----------|------|------|
| 01 | AIの研修、聞くだけで終わっていませんか？ | テキストを読みながら、その場で試せる | チャット画面でハンズオンテキストを開く → 第1章の例文を「入力」ボタンで入力欄へ → AI が答える | 読みながら学ぶ ／ そのまま試せる ／ その場で確かめる |
| 02 | 「このプロンプトを打ってください」全員そろうまで、待っていませんか？ | 講師のプロンプトを、全員の画面へ | 講師（/presenter）が「配信」→ 受講者の画面に「講師からのプロンプト」→ 入力欄に入れて送る | ボタンひとつで配信 ／ 全員が同じスタートラインに ／ 打ち間違いも、待ち時間もなし |
| 03 | 研修のあと、本当に理解できたか分かりますか？ | 理解度は、AI が作る確認テストで | 確認テストを始める → 1 問目 → 答える → 解説 →「もう少し簡単に説明」 | 受けるたびに、新しい問題 ／ 間違えても、その場で学べる ／ もう少し簡単に |
| 04 | AI を使うと、どれくらいコストがかかるか知っていますか？ | AI の使い方が、数字で見える | 2 回質問した後に利用状況のダッシュボード → 推定コストのタイルを裏返して単価 → モデル別の比較 | 質問の回数とトークン ／ 推定コストが分かる ／ 賢い使い方が身につく |

## 3. 作り方

**画面を Playwright で操作して撮り、ffmpeg で 1 本にまとめる。** 台本がコードなので、画面や文言を直しても
同じ動画を作り直せる。

| 置き場 | 役割 |
|--------|------|
| `promo/lib/recorder.mjs` | 撮影の土台。CDP の screencast でフレームを時刻つきで保存する。矢印カーソルを足し、Next.js の開発用バッジを消す |
| `promo/lib/render.mjs` | フレームを mp4 にする。待ち時間の早送り（`retime`）と字幕の帯の合成、カードの動画化、つなぎ |
| `promo/lib/cards.mjs` | アプリの画面ではない場面（問いかけ・タイトル・締め）の画 |
| `promo/scenes/*.mjs` | 素材ごとの撮影台本（何を押し、どこで待つか）。`common.mjs` は共通の操作 |
| `promo/build.mjs` | 4 本の構成（各場面の秒数と字幕）。素材を切り出して 1 本ずつつなぐ |
| `promo/out/` | 撮ったフレームと書き出した動画（Git 対象外） |

決めたこと（BoX4 の CM と同じ）:

- Playwright 標準の録画（recordVideo）は画質が粗いので使わない
- アプリの画面は 1280x620 の広さで組み、1.5 倍の密度で撮る（= 1920x930）。残りの下 150px が字幕の帯
- AI の応答待ちは、目印（`rec.mark()`）の間を数秒に縮める。字幕の切り替えも秒ではなく目印で書く
  （撮り直しても字幕と画面がずれない）

### 撮影の前提

- llama.cpp のモデル 1（8080）と**モデル 2（8081）の両方**が動いている。dev サーバは `.env.local` のまま
  （`npm run dev`、3000 番）
  - テキストのパネルを開いている間は、アプリが常にモデル 2 を使う（`app/page.tsx` の `onPageChange`）。
    確認テストも既定はモデル 2。台本のチャットも、既定でモデル 2 を選ぶ（`scenes/common.mjs` の `openChat`）
  - モデル 2 の代わりにモデル 1（12B）で確認テストを作らせると、出力が長すぎて途中で切れ、10 分待っても 1 問もできなかった
    （2026-11-05）。モデル 2 を止めたまま撮るのは避ける
- `.env.local` に `PRESENTER_PASSWORD` がある（CM 02 で講師の画面にふつうにログインする）
- OCC のロゴを `promo/out/assets/occ-logo.png` に置く（会社の素材なのでリポジトリには入れない。
  cheetah-frame の `apps/web/promo/out/assets/` と同じもの）
- ffmpeg が入っている

### 撮影と書き出し

```bash
node promo/scenes/cm1-text.mjs        # 約 2 分
node promo/scenes/cm2-broadcast.mjs   # 約 2〜4 分。撮り終わると配信を取り下げる
node promo/scenes/cm3-quiz.mjs        # 約 2〜4 分
node promo/scenes/cm4-usage.mjs       # 約 2 分
node promo/build.mjs                  # 4 本と、つないだ 1 本を promo/out/ に書き出す
node promo/build.mjs cm2              # 1 本だけ組み直す
```

- **台本は 1 本ずつ流す。** 同時に流すと AI の応答が遅くなり、「応答に時間がかかっています」が写ることがある
- CM 02 は実際に配信する。同じ dev サーバにつないでいる受講者がいれば、その人の画面にも出る
- AI の答えは撮るたびに文面が変わる。撮り直したら書き出した動画の中身を見ること

直すときに触る場所:

| 直したいこと | 触る場所 |
|--------------|----------|
| 字幕の文・各場面の秒数・問いかけ・タイトル | `promo/build.mjs` の `CMS` |
| 操作の中身（入力する文・押す順番・待つ長さ） | `promo/scenes/*.mjs` |
| カードの文言と見た目（締めを含む） | `promo/lib/cards.mjs` |
| 帯の見た目・配色・画質 | `promo/lib/render.mjs` |

字幕やカードだけを直したなら、撮り直さずに `node promo/build.mjs` だけでよい。
